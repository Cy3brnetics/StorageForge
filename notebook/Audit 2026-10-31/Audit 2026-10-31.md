# Audit 2026-10-31: security and new features

**Short version:** the new scheduler should not ship as it stands. Most of the rest is sound. Roles, invites, the file map and the disk health collector are well built, and the serious problems cluster in the scheduler and the Git Inspector, which skip protections the older deploy path already had.

| 1 | 8 | 14 | 5 | 28 |

**Status:** steps 1 to 4 of the fix order are fixed, except part of PF-23 and the lab runs PF-25 and PF-26 wait for. Steps 2 to 4 have not run on a real host or in the KVM lab. Found while fixing and now fixed: [[SF-39 Task command blocks are a root shell without schedules.command|SF-39]]. The tables below show severity as found.

## The three to read first
1. [[SF-23 Run local executes schedules on the server\|SF-23]]: **Run local** lets an operator run shell commands on the StorageForge server, and from there read the vault secret. Remove it.
2. [[SF-27 Git commands run code planted in a repository\|SF-27]]: any local user on a scanned host can plant a Git repository that runs code as the scan account during a scan. This one dates from 10-26, and earlier audits missed it.
3. [[PF-18 Schedule reports over 4 KiB are refused\|PF-18]], [[PF-19 Deleting a deployed schedule orphans a root cron job\|PF-19]] and [[PF-20 Pausing a schedule does not stop it\|PF-20]]: a run printing over 4 KiB can't report, a deleted schedule leaves a root cron job nobody can remove, and pausing doesn't stop anything on the host.

## What was done well
Worth keeping when the fixes go in:
- `permissions.required` denies by default, and `test_every_route_is_listed` walks the URL map so that a new route can't be forgotten.
- With no session, every `/api` route answers 401 except sign-in, sign-out and the enroll routes (proven by walking the URL map).
- No use of `innerHTML` with data in any new JS file. The older planner still uses it, and was out of scope.
- Tokens and session ids are stored only as hashes. Webhook URLs are checked with a DNS lookup before saving. `may_hand_out` stops privilege escalation through accounts, invites and roles.
