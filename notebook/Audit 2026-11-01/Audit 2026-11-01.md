# Audit 2026-11-01: remote nodes, snapshot engine, and multi-tenant isolation

**Short version:** do not ship until the snapshot discovery fallback and remote node retirement lifecycle are addressed. The new remote reverse SSH tunnel architecture is conceptually sound and locks down SSH privileges tightly with forced commands and loopback restrictions, but retiring an adopted host leaves its reverse SSH tunnel active and authorized indefinitely. The snapshot discovery probe silently drops all snapshots if the capability binary is unexecutable. Origin validation omits port comparison on fallback.

## The four to read first
1. [[PF-29 Snapfind fails silently if capability find is unexecutable|PF-29]]: snapshot discovery shell probe fails silently and returns empty results when `/usr/local/lib/storageforge/find` has restricted permissions or capability mismatches, masking all backups.
2. [[SF-40 Retiring a host leaves remote reverse SSH tunnels orphaned|SF-40]]: retiring an adopted host deletes the host database record but leaves its remote node tunnel authorized in `authorized_keys`, keeping the reverse SSH tunnel active indefinitely.
3. [[SF-41 Remote nodes overview rewrites authorized_keys on GET and blocks on offline nodes|SF-41]]: `GET /api/remote/nodes` rewrites `authorized_keys` to disk on every read-only request and sequentially checks node ports with 2s timeouts, risking worker thread exhaustion.
4. [[SF-42 Same-origin fallback omits port comparison on cross-origin requests|SF-42]]: when `Sec-Fetch-Site` is absent, same-origin validation compares hostnames without ports, allowing cross-port CSRF from other local loopback services.

## Fix order

### 1. Fix the broken snapshot probe and report routes
- [[PF-29 Snapfind fails silently if capability find is unexecutable\|PF-29]]: update `snapfind.py` to test actual execution of `/usr/local/lib/storageforge/find` and fall back to standard `find`.
- [[PF-28 Job reports over 4 KiB are refused with 413 Payload Too Large\|PF-28]]: expand `body_limit` in `server.py` for `/api/jobs/report` and `/api/jobs/state` to 512 KiB.

### 2. Close remote node lifecycle and availability gaps
- [[SF-40 Retiring a host leaves remote reverse SSH tunnels orphaned\|SF-40]]: revoke remote node and call `remotes.sync()` in `retire.retire()`.
- [[SF-41 Remote nodes overview rewrites authorized_keys on GET and blocks on offline nodes\|SF-41]]: remove `sync()` from `overview()`, and make connectivity probes non-blocking or asynchronous.
- [[PF-30 Remote node IP address calculation wraps and allows broadcast addresses\|PF-30]]: validate node ID bounds and skip network/broadcast octets.
- [[EQ-06 Missing test for retiring remote node hosts\|EQ-06]]: add lifecycle integration tests covering adoption and retirement of remote nodes.

### 3. Harden origin checks and site reset
- [[SF-42 Same-origin fallback omits port comparison on cross-origin requests\|SF-42]]: compare `netloc` (or scheme, host, and port) in `same_origin_only`.
- [[SF-43 Site reset abandons old vault secret in file when new secret is provided via environment\|SF-43]]: ensure `_install_secret` writes to `STORAGEFORGE_VAULT_SECRET_FILE` when a new secret is supplied via environment.

## What was done well
- Remote tunnel forced command restriction: `authorized_keys` specifies `command="/bin/false",no-pty,no-agent-forwarding,no-X11-forwarding,permitopen="127.0.0.1:*"` locking dialed-in nodes strictly to their designated loopback port forwarding without shell access.
- Multi-tenant vault secret isolation: random 32-byte tokens generated with `secrets.token_hex(32)`, secrets stripped from logging and client payloads.
- Safe DOM handling in filemap: pure DOM creation via `document.createElement`, escaping attributes and preventing XSS when displaying user-controlled filesystem paths and snapshot labels.
- Test suite coverage across core units: 558 unit tests passing across storage ops, auth, roles, invites, and scheduler.
