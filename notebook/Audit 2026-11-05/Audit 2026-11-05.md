# Audit 2026-11-05

**A partial audit: it stopped when the working session ran short, and says what it did not reach.** Baseline `d78881b`, head `fc1bb8a`, 40 commits and about 8,200 new lines in the package, with the working tree clean (only `.obsidian/` untracked). It was run by the model that also built part of what it audits, which the first reader should weigh.

## Short version
No verdict that the release is safe to ship: the audit did not reach enough to give one. What it did reach is well built. The network device code follows the promises the docs make: a password goes only over a host key a person confirmed, the network language checks every field against a list of what it takes, credentials are never returned and never stored in the clear, and every untrusted XML source refuses entity declarations. It found one Medium and three Lows. The Medium is the only one with a real effect: a host's log lines can stall the server ([[SF-52 One long log line holds the whole server for a second or more|SF-52]]).

## Verdict per feature
- **Network device transports and credentials:** built the way the invariants say. Keep.
- **The network language and its compilers:** well guarded, with one gap in free text ([[SF-53 A comment in the network language can hold text-direction and zero-width characters|SF-53]]). Keep.
- **Host logs:** the scrubber needs bounding ([[SF-52 One long log line holds the whole server for a second or more|SF-52]]); CSV export already neutralises formulas.
- **The signed receiving run (SF-48):** built by a delegated model, tested against a real `sshd` and by 93 tests; read by this audit in part (its module header and the design), not line by line. Needs the lab.
- **Signed scan payloads:** written the same day by the model that ran this audit, so its own review of it is not independent. It needs a second reader and the lab.
- **The UI kernel, router and shared chrome:** written in this session and read while being written; dialogs and drafts show text and never markup, which a test holds. Needs an independent read.

## What was done well
- Every free-text field of the network language has a validator that is a regular expression matched with `fullmatch`, so a trailing newline cannot slip through.
- A password to a device goes only after `require_confirmed` and over `StrictHostKeyChecking=yes`, and travels in the child's askpass environment, never on a command line.
- `hostlogs` export passes every cell through the shared formula neutraliser.
- No `shell=True`, `os.system`, `yaml.load`, `pickle`, `eval` or `exec` anywhere in the package. `StrictHostKeyChecking=no` appears only in the two probes that collect a key for a person to confirm and send no secret.
- The route table is default-deny and a test fails when a route is missing from it or from the fresh-password table.
