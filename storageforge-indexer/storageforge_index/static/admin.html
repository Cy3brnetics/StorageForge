      SSH certificates

      A certificate authority kept in the vault. A host that trusts it lets StorageForge in with a certificate that lasts minutes and names one user on that host, and a certificate can be revoked. Keys in authorized_keys go on working: trusting the CA takes nothing away.

      Secrets for plan steps

      Passwords, tokens and keys that plan steps need on a host, made here and kept in the vault. A value is shown once, when it is made or rotated, and then never again: a plan step gets it on the host through the signed runner, when the plan is applied.

      Platform connections

      Proxmox VE, Backup Server and Datacenter Manager read through their own APIs, beside SSH. First what the token needs, the least that works and never root or a full-access role; then the token, kept in the vault; then the platform's certificate, which you accept before the token is sent anywhere. Read-only unless you turn an action on. Not lab-tested.
