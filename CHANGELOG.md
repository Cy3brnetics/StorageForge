# Changelog

Newest first. Releases are tagged `vX.Y.Z`. Everything before 0.3.0 was 0.2.0 and was never tagged.

## Unreleased

### Added
- **`storageforge-index rotate` changes every key StorageForge holds, for when one may have leaked.** Without `--apply` it lists each vault SSH key with the hosts and accounts that use it, and what it cannot change. With `--apply`, each key gets a successor that is added to every account that uses it and tried there first; only when every host takes it do the bindings move, the old line come out of each `authorized_keys` and the old key go. One host that refuses leaves the old key in place everywhere. It also ends every web session, revokes unused invites, and with `STORAGEFORGE_VAULT_NEW_SECRET` wraps the vault under a new secret. A key that is in an `authorized_keys` where no binding uses it is named, since a rotation cannot reach it. What it cannot change (session secret, TLS certificate, report tokens, scan signing keys, device passwords, alert addresses) it lists with what to do. Tried in the lab on 2026-11-07: the scan key changed on all seven hosts, the old fingerprint gone from each, and every host scanned with the new key. See [If a key may have leaked](docs/security.md#if-a-key-may-have-leaked).

- **Scans read the packages a host was given on purpose, and `hosts packages` installs the same set elsewhere.** The list holds the distro and version, what was installed on purpose rather than pulled in (`apt-mark showmanual`, `pacman -Qqe`, `dnf repoquery --userinstalled` from the cache, then its history, then every package; zypper's packages less its automatic ones; apk's `world`), Flatpak and Snap apps, AUR packages kept apart, and the package sources with any user, password or query taken out. `storageforge-index hosts packages HOST` lists it, `--against HOST` compares two hosts, and `--script` writes a script that reports what the machine it runs on lacks and installs it with `--apply`. It never removes a package to make room for another: apt runs with `--no-remove`, zypper and apk are simulated first, and a removal is a conflict naming the packages. Names are never translated between package managers, and sources are listed, never added. Also `GET /api/hostconfigs/packages` and `/api/hostconfigs/packages/script`. Hosts show a list from their next scan. It is the first step of [cloning and migrating hosts](docs/host-migration.md). Unit-tested against stand-in package managers and on one Arch host, **not lab-tested**.

- **VMs from cloud images, as a change plan step (`vm-create`), and VM specs.** On a scanned libvirt host, a VM is made from one of 15 cloud images (Debian, Ubuntu, Fedora, Rocky, AlmaLinux, openSUSE, Arch, Alpine) or your own image with its checksum. The image is downloaded once into the pool, checked against the checksum its publisher lists, and copied to a new root disk; data disks and a cloud-init seed with one login account for your SSH key are made, and `virt-install --import` starts it. Firmware, CPU model, console, network or bridge, and autostart are fields. It never writes over a disk or a VM that is there, and never touches a VM StorageForge did not make. The check reads the host's last infrastructure reading: libvirt present, the pool and network, the room, a name already taken, whether the key is in the vault. A **spec** fills a step's empty fields when the plan is saved, so a saved plan says everything it does; `small`, `server`, `desktop` and `test-copy` are built in. `storageforge-index vm images|specs|spec|spec-remove|create|clone`, `GET /api/vm/images`, `/api/vm/specs`, and **Create a VM here…** on a host in the web UI. `test-copy` and `vm clone --test` use `sf-isolated`, a libvirt network only the libvirt host reaches, made on first use. Unit-tested against stand-in libvirt tools, **not lab-tested**.
- **A `packages` step installs another host's packages,** from its last scan, as a step of a change plan, and `vm clone SOURCE` saves the two plans that copy a host to a new VM: the VM, then the source's packages once the VM is scanned. Config, user files and the snapshots and warnings in the [design](docs/host-migration.md) are not built yet. **Not lab-tested**.
- **The package list knows image-based, transactional and read-only systems, apt on rpm, and Debian's holds, backports and local packages.** Fedora Silverblue, Kinoite, CoreOS and bootc systems give the packages layered onto their image (and name the image); MicroOS and Aeon install through `transactional-update`; SteamOS and Ubuntu Core give only their apps; ALT Linux and PCLinuxOS are their own family. Held packages are held again, backported ones come from backports, and `.deb` files from no source are listed like AUR packages, which now keep their versions. **Not lab-tested**.

### Added
- **The storage planner keeps named versions of a design (migration 042).** Save one with a note, compare it with the design on screen in plain words, restore it (the design it replaces is kept as an automatic version first) or delete it. At most 50 versions and 40 MiB per host, included in essential backups.
- **Logs is a view of its own.** A time range (hour, day, 7 or 30 days, or from and to), a chart of lines by level and hour with a pattern per level, when each host's journal was last collected (or that it never was), a unit filter fed by the stored units, and a link from a host's Details. The range and filters are in the URL.
- **The map's what-if answers in plain sentences, worst first,** with the technical lines behind Details, and the map has zoom, reset and Fit to screen controls and a legend in words.
- **A Ctrl+K command palette and a `?` shortcut help, per-browser Preferences (theme, density, reduced motion), a first-run checklist on an empty install, shapes as well as colour on health and status marks, and a tablet header** that folds its extra controls behind a More button.
- **The Logs view has two helpers: `GET /api/hostlogs/counts` and `GET /api/hostlogs/units`.** The first gives stored host log lines by level and by UTC hour (at most 792 hours, newest kept), the second the units a host has logged with a line count each, most first and at most 200. Both take `hostlogs.view`. Lab tier 14, which runs host logs on real journald, is written and has not run: **not lab-tested**.
- **Lab tier 17 applies the network language on firewalld and ufw hosts and reads the rules back.** Written, not run: **not lab-tested**. Tests also run the Terraform and Puppet exports through `terraform validate` and `puppet parser validate` when those are installed (skipped here, where neither is), and check that the CI workflow files parse and hide nothing. The lab page now says "not lab-tested" for real pfSense, OPNsense and Cisco devices, old SSH ciphers, Incus and LXC guests, Tailscale, proxies and identity providers, Terraform and Puppet apply, PagerDuty, FIDO2, signed scan payloads and the SF-48 receiving run.
- **A list that shows only its first rows says how many it leaves out and has a real "Show N more" button.** It opens in place, reads "Show fewer", works from the keyboard and is announced to screen readers. It covers seven security tables that cut silently, the file map's link and largest lists, the Moves "only these files" line and the access check's refused folders.
- **A device's rollback folder is made fresh and private (SF-55).** On OpenWrt and pfSense it is made with `mkdir -m 700` and no `-p`, so a folder or link that is already there fails the plant, and a failed step ends the plant script, which used to print "planted" regardless. Unit-tested under a stand-in shell, **not lab-tested**.
- **Scans collect host logs.** Each scan picks up what is new in the host's journal: up to 2,000 lines at warning or worse and 5,000 at info or worse. Search them by host, level, unit, text and time in the Logs tab, `hostlogs` on the CLI or `/api/hostlogs`, and export them as CSV, JSON or text. Nothing tails or streams: to see newer lines, scan the host. Lines are kept 30 days and at most 500,000 per host (`STORAGEFORGE_LOG_KEEP_DAYS`, `STORAGEFORGE_LOG_KEEP_ROWS`). `STORAGEFORGE_HOST_LOGS=0` turns collection off.
- **Hosts need their scan access script run again to collect logs.** It now adds the scan user to `systemd-journal`, which lets that user read everything in the journal. Until then the Logs tab says so for that host and stores nothing.
- **Reading host logs takes a new permission, `hostlogs.view`.** Operators and admins have it. Viewers don't, because journals hold sign-ins and sudo commands. Custom roles don't get it on upgrade.
- Known secret shapes are removed from lines before they are stored (passwords, tokens, API keys, URL credentials, private keys). This catches common forms, not every form.

### Security
- **A host's report can no longer write holds or quarantines, or make the worm check pass (SF-70).** A `brake_ran` line from a host is only an event now. The signed brake run writes the rows, and checks each value first.
- **A host with a report token can no longer fill the database (SF-73).** At most 300 events an hour per host and 100 of any one kind, detail cut at 2,048 characters, an `events_dropped` warning once an hour, and old acknowledged events pruned.
- **A host that signed before is refused when it answers unsigned or under a new key (SF-74),** even with `scans.require_signed` off. To accept a replacement, forget the host's key (`access signing --forget`). A cut-short signature is a `BadSignature`, and the signing switch reads only true/false text (SF-75).
- **Decoys are built in a private folder (SF-71),** so a name in a world-writable share cannot be swapped for a link between steps. **A ZFS receive takes no exports, setuid or devices from the stream (SF-72, partly):** `-x sharenfs -x sharesmb -o setuid=off -o devices=off -o canmount=noauto`, so a received dataset no longer mounts at boot. The btrfs side and a hostile-stream lab run are still open, **not lab-tested**.
- **OpenWrt readings no longer store WireGuard keys or passwords (SF-62).** Rows stored before are cleaned when read. Reading a device change needs `security.view` (SF-63). The compile route takes at most ten different known targets (SF-60). The network language refuses IPv6 zone text and non-ASCII digits (SF-64). A RouterOS change stops before its first command if its rollback timer could not be set, and any failure before the timer is on leaves a change at `reported` on every platform (SF-61). `sshd-option` and `apparmor-local` keep errors in a `mktemp` file (SF-65). All unit-tested, **not lab-tested**.
- **The change plan and planner drafts are kept per account in the browser (SF-80).** A second account on the same browser no longer sees the first one's draft; drafts from earlier versions are removed.
- **Scan payloads are signed on the host and checked before they are used.** Everything a scan reads from a host (the inventory, each folder walk, the checksum pass, the journal, the network, container and git surveys) comes back with a signature over a fresh nonce and the SHA-256 of exactly the bytes the host sent, made with `ssh-keygen -Y sign` in its own namespace. A payload that does not verify, was signed by another key than the one pinned for that host, or differs from what was signed, is refused: a refused walk leaves its mount's index as it was, and a refused inventory stops the scan before job runs, ClamAV results or security events in it are taken in. The key is a scan signing key that read-only scan access now makes and StorageForge pins over the host-key-confirmed setup connection, or the host's SSH host key when scanning as root. Hosts that cannot sign are shown as unsigned, and `storageforge-index access signing --require on` refuses them. **Upgrading:** run the read-only scan access setup again on each host so it gets its signing key; until then its scans are used and marked unsigned. Needs OpenSSH 8.0 or later on the host to sign. **Not lab-tested:** tested here with the real wrapper and a real `ssh-keygen`, through a stand-in transport that runs `sh` on this machine.
- **Each side of a btrfs or ZFS send is a signed run, and no root key is needed between the hosts (SF-48).** The receiving host used to run root commands on the word of the sending host's own root key, with no signature, no nonce and no record there. Now the receiver gets a signed conf that says what it may receive and where, and a key whose forced command can ask for nothing but that send's verbs; the sender sends with that key, and the receiver keeps its own run record. There is no unsigned way: a send to a host that is not enrolled is refused, with the steps to enrol it. **Upgrading:** a plan that sends to another host needs that host enrolled (Deploy, **Set up**), any root key you made between hosts for sends can go, and a task already installed keeps its old script until it is deployed again. `rsync` to another host inside a task block is still unsigned, and [security.md](docs/security.md) says what to use instead. **Not lab-tested:** it is tested against a real `sshd` with stand-ins for `sudo`, `btrfs` and `zfs`, and lab tier 16 is written and has not run.
- **One long log line can no longer hold the server (SF-52).** The host-log scrubber's first two patterns read on from every character of a long run of word characters, so one 4,000-character line took 0.7 seconds and a line made of the word `pwd` over and over took 2.5 minutes, with every web request waiting. Both now start only where a run starts, a cheap check skips the secret patterns on a line with none of their words, and the worst line at the cap takes about 3 milliseconds. What is redacted is the same as before. Found by the audit of 2026-11-05.
- **A comment in the network language cannot hold a text-direction or zero-width character (SF-53), and no source file holds a bidirectional control (SF-54).** A right-to-left override in a comment could reorder what a person reads in the review screen or on a device's own log. It is refused now, with the character named. The two source files that held such characters as literals write them as escapes, and a test fails if any source file holds one.
- **A test walks every route that can end in a hold (SF-46).** It builds the package's call graph from what signs a script that holds snapshots back to the URL map, so a new route, policy or playbook is found without anyone naming it, and checks that each takes the permission a hold takes. It found seven routes and nothing to fix.
- **The sentinel has its own permission, `security.sentinel`.** Setting it up takes it. Deploying, re-arming and removing it take it and `deploy.apply`. Operators no longer hold it: `deploy.apply` alone could take the sentinel off a host. Custom roles with `security.emergency` get it on upgrade, to keep what they could do.
- **A security key guards its own replacement.** Adding or removing a key on an account that has one takes a touch. `user clear-keys` is the way back from a lost key.
- **Retention policies take `security.emergency`,** as a hold does. Operators could apply legal holds through them. They can still preview.
- **`/api/security/evidence` is a POST, needs `audit.verify` as well, and is limited to 10 a minute.** A viewer could unlock the vault with a GET.
- **Falco's signing key is pinned,** and its repository file is written by the script, not downloaded.
- **Map views belong to whoever saved them.** Others see one only if it is shared, and can't change it.
- Comparing a design no longer writes to the database. Audit rows name the second hosts a send logs in to, and the check warns about them plainly.

### Fixed

The task and schedule installers now give their scripts `bin_t`, with a persistent rule when `semanage` is there. Lab tier 16 passes in full, including the six ZFS sends on two ZFS hosts.
- Rule sets, map views, designs and long sentinel events over 4 KiB were refused before their validators saw them.
- Malware preview answered `GONE` for a quarantined file. It now says the file is in quarantine.
- Removed `backup.send_file`, an unsigned sender nothing used, and a site-wide security key setting nothing could set.
- **A slash typed into a text field arrives.** `/` moved focus to the search box from anywhere, so a path lost its first character and started a file search. A password with a slash in it lost the rest of itself into the search box, and from there into the server's request log; in the confirm dialog the slash vanished, so that password could not be typed at all. The shortcut now acts only when nothing is being typed and no dialog is open, and the other shortcuts follow the same rule: `\` leaves an open dialog alone, the menu key and Shift+F10 leave a text field's own menu alone, and so do Ctrl+Z in Tasks and Escape.
- **Escape asks before it throws away a half-made share.** In the share wizard, Escape after the first step with something changed asks first. The Close button still closes at once.
- **The side rail says when it goes on.** On a laptop it needs about 1000 pixels and its scrollbar is hidden, so Security, Scans, Keys, Logs and Audit were out of sight with nothing to say so. The last visible button now fades, a chevron scrolls the list, and a panel opened from a link scrolls into view. The group labels are 10 pixels at full strength instead of 8.5 pixels at 70%.
- **`Export .canvas` is no longer the header's one blue button,** and it shows only in Topology and Graph, where it exports what is on screen.
- **The planner keeps keyboard focus when a field is changed.** Every change redrew the whole view, so Tab out of an edited field dropped focus to the page and a keyboard user had to tab in from the top again. Focus and caret now stay where they were, Enter in the new-subvolume field keeps the field for the next one, and changing view from the keyboard keeps focus on the navigation.
- **"Offsite" in the planner is what the design says, not what a name looks like.** The 3-2-1 column counted a replica as offsite when its target's name matched `nas-02`, `office`, `b2` or `S3`: names from the example, so on a real fleet a machine called `office-nas` on the same LAN read as offsite. A replica now counts only when the design or the deploy says it is offsite. One nobody said anything about reads *offsite not stated*, and a row with a replica and no backup no longer calls the replica a backup.
- **Text colours that missed 4.5 to 1 now clear it:** the planner's column heads and labels in both themes, the light theme's Access badge, and the status colours on the `/manage` page background. A test reads the stylesheets and holds every text colour to it.
- **A list that is cut says so.** "Needs attention" in Details listed twelve broken things and said nothing about the rest, and the map's lists of changes, uncovered workloads and sentinel warnings, and the design comparison, stopped at 10 to 30 rows the same way. Each now says "+3 more", and the same button shows the rest and puts them away again. The other lists that cut their rows without saying (the Security tables, the file map's) wait for the shared list component in phase 1 of the [UI roadmap](archive/roadmaps/ui-ux-roadmap.md).
- **Details says what it is for in every view.** In Map, Tasks and Scan it kept the graph's instructions and counted storage-graph nodes that were not on screen. Each view has its own hint, and a node picked in Graph is still picked when Graph comes back. On the map the preset that shows only storage is "Storage only", no longer a second "Storage" beside the layer, the presets and the layers have their own captions, and picking a layer by hand marks no preset as pressed.
- **Compose's button says what it will do.** On `/manage` it said "Report" for everything, though a Linux host's rules become steps in Changes and only a device is checked. It now reads "Stage in Changes" for a host and "Check" for a device.
- **The security chip in the header always starts "Security: " and shows its detail.** The secure state read "Nothing wrong found" with no label, and the detail was a tooltip that no keyboard or finger reaches. It is now two lines on the chip, with the whole of it still on hover, and its secure green is the theme's own: the fixed light green was 2.0 to 1 on the light theme.
- **The security chip is on every page.** The changelog said "a line at the top of every page" and only the main page had it. `/planner` (in its page header), `/manage` and `/search` now show the same chip, drawn by the same code, and a click opens the Security panel. Those pages also get the links between the pages and the site and user, and **Sign out**, which the planner and `/manage` never had.
- **Every global keyboard shortcut is declared in one place.** `/`, `\`, Escape, Menu, Shift+F10 and Ctrl+Z each checked for themselves whether somebody was typing, which is how `/` took a slash out of a path. They now declare themselves with `sfShortcut()` in the kernel, which applies one rule (not in a text field, not under a dialog, not with Ctrl, Alt or Meta held, unless the shortcut says it may) and keeps the list a help overlay can show. A test fails when a script registers a global key handler of its own. A key event with no `key` (some browsers' autofill sends one) no longer throws in the Tasks shortcut.
- **A time is shown one way.** Seven small formatters showed times three ways: UTC with no label in the logs, the audit log and invite expiry, local time in jobs, backups, the map and `/manage`, and "UTC" written out in one place. A time is now local, `2026-11-05 03:14`, with its UTC form on hover where it is an element (log lines and audit entries have it), and "5 min ago", "in 2 h" and "13 months ago" come from one function, as do sizes. A test fails when a script formats a time or a size itself.
- **Work in progress survives more, and the page says what it could not keep.** Compose's text and the steps staged on the map were in memory only, so a reload threw them away. Both are now kept in this browser as they are typed or staged, for the account that wrote them, so another person on the same browser never sees them, and **Load what it runs** asks before it replaces text you wrote. One rule covers every editor: it asks before the page closes on work that would be lost (a design edited in Topology, a task, a move plan) and says nothing when a draft is already kept (Compose, the map's steps, change plans, the planner). When a session ends under you, the sign-in page names what was kept in this browser and what could not be.

It is now `/#/graph/changes?host=nas-02`: a copied URL lands where it was copied, each view, panel, host and Security sub-panel you choose is a step Back and Forward walk through, the map writes its preset or layers and filter, and links inside the page change the hash without reloading. The planner (`/planner#/devices?host=nas-02`) and `/manage` (`/manage#/compose`) do the same. The old forms (`#host=…&tab=…`, `#view=map&…`, `#devices@nas`, `#device=gw`) still open where they always did, and are rewritten as the new one.
- **Security and the settings get the whole page, and the rail is a real tab list.** Sixteen security panels and the accounts, roles and invites were laid out in a 380 px column. Security, Audit (accounts, roles, invites, backups, your password), Keys, Scans, Access and Logs now open across the page with the view out of the way, a button in any panel's header does the same for that panel (remembered per panel), and hiding the panel gives the view back. Security's sub-panels are grouped Prepare, Detect, Respond and Prove with the posture on top. The rail is one tab stop with Up, Down, Home and End, each tab names its panel and each panel its tab (`aria-controls`, `tabpanel`), a skip link goes to the view or the panel, and the group that held the inventory is called Estate. The groups are not collapsible: a button inside a tab list breaks the tab pattern, and the long groups now leave the rail's way instead.
- **The map can be used from the keyboard.** It was an image to a keyboard and a screen reader. Every node is now a button in reading order, each host's header followed by what is in its frame; Enter shows a node's details and tells a screen reader where they are, Enter on a host's header closes or opens it, and Space shows its details. The map says how many items it holds instead of `role="img"`.
- **A panel about one host carries its own picker.** Security's host-bound panels, the Infra views that need a host and what a scan changed told you to pick a host at the top of the page. They now show a picker, starting on the host with the most findings in Security's case, and choosing one sets the page's host. The view buttons say what each view is for, and the planner and `/manage` lead into Changes, Moves and Schedule.
- **A button that is working says so, and cannot be pressed twice.** Every button built by the main page's `button()` and `/manage`'s `btn()` shows a spinner and `aria-busy` while its async handler runs, and ignores a second click or Enter meanwhile. It is not `disabled`, which would have lost a keyboard user's place when a dialog it opened closed.
- **Scan groups hosts by the ranges that were scanned.** Every address went under an assumed /24, so one /20 could come out as up to sixteen networks and a /25 shared a heading with its neighbours, and a range that found nothing was not shown. The server now says which scanned range each address falls in (the narrowest, when ranges overlap), the page groups by that in the order the ranges were named, shows an empty range with "Nothing answered", and puts anything outside them last. The same grouping serves `/api/netscan/graph`, and an address that is not IPv4 no longer breaks the sort.

### Added
- **One [roadmap](roadmap.md) of what's left.** Finished and superseded roadmaps moved to [archive/roadmaps](archive/roadmaps/).
- **Routers, switches and firewalls.** MikroTik RouterOS and OpenWrt, through the KVM lab on real images, and pfSense, OPNsense and Cisco IOS, tested against published formats only. A device's interfaces, routes, firewall and NAT land in the same records a host's do, so the map, reach and exposure all see them. See [Network devices](docs/network-devices.md).
- **Paths through routers.** The path query walks router by router and through port forwards, naming the rule that decides. A listener a router forwards to now shows as reachable from anywhere, which used to be out of sight.
- **One network language.** RouterOS syntax, compiled for RouterOS, nftables, iptables, firewalld, ufw, OpenWrt, pfSense, Cisco, networkd and NetworkManager, saying what each target can't express. Any firewall reads back in the same syntax.
- **Device changes with a rollback on the device.** A report first, then an apply that plants a timer on the device before anything changes. A change that cuts StorageForge off undoes itself.
- **A management planner at `/manage`.** Every host and device in one list, and one place to write a change, see what it becomes, and ask what it would do to a path.
- **A network scanner, off by default.** nmap, in a Scan tab beside the map, only of private networks someone named. Results link back to each machine's pages. Nothing else in StorageForge sends a packet to find out what exists.
- **Traffic monitoring, off by default.** Interface rates over time from devices' own counters, and what stands out in them.
- **An infrastructure map.** Networks, firewalls, listeners, containers, VMs and VPNs across hosts, drawn from what they report, with evidence on every line and no probes. Layers and modes, grouping, saved views, notes, things placed by hand, a timeline of earlier readings, and exports to SVG, PNG, PDF, Mermaid, DOT, draw.io, canvas and JSON, redacted if you ask. See [Infrastructure map](docs/infrastructure-map.md).
- **Who can reach what.** One exposure engine over nftables, firewalld, ufw, iptables and Docker's NAT, which says *unknown* rather than guess, and shows a port ufw looks like it blocks as reachable. **Can A reach B?** names the rule that decides it and lists what it cannot see.

### Security
- **A planner or dry-run account could run root commands on a host.** `POST /api/deploy/start` with `mode: report, run: true` ran the script for real on `deploy.report` alone, and `remove: true, run: true` skipped the `hosts.command` check. `task_type: "Command"` got past that check when saving a schedule. Now `run` needs `mode: apply` and refuses `remove`, the check reads the type as it will be saved, and pausing an installed schedule that changed since its deploy takes `hosts.command` if it now holds commands.
- **Schedule environment variables are for command schedules only.** On a plan or task they could change a program its script calls (`RSYNC_RSH`, `TAR_OPTIONS`). Existing rows keep theirs on record, and no longer deploy them.
- **State-changing requests must come from this origin.** A page on another port of the same host counts as the same site, so `SameSite=Strict` let it post forms here.

### Security
- **Backup copies on another host are encrypted**, with a key from the vault secret. They hold password hashes and alert tokens. `restore` takes them as they are. Without the vault secret, no copy is made.
- Invite and reset links die when their role comes to allow more. A reset link also dies when its account is replaced or changes, and a new link cancels the last one. **Open links made before this update stop working: make them again.**
- `backups.manage` and `settings.manage` are marked high risk. A retired host can't still have schedules. A job's `.git` link can't point outside its source.
- A Git repository can no longer run code as the scan account through its own config. Git runs with those settings off, and `git status` runs only in repositories the scan account owns; others show **Not checked**. Git routes take only repositories a scan found.
- **Git sync needs deploy access.** Sync is now a signed run, as the repository's owner, with hooks off and a fresh password for every action. Git status, history and commit are POST only, rate limited and audited.
- The log fetch after a failed task refuses odd task names and no longer copies all of `/var/log/messages`.
- A task's timer no longer rewrites the deploy runner. **Redeploy existing tasks**: copies already installed keep doing it until then.
- Raw commands need a new high-risk permission, `hosts.command`, to write or deploy: command schedules, a task's **Run command** blocks and **command succeeds** conditions, and a move step's pre and post commands. Only `admin` has it by default, so operators who use them need a custom role. A move's `docker compose -p <name> stop` and `start` hooks stay open to `plans.edit`, and anyone can take commands off a host. Env variables that change what runs (`PATH`, `LD_*`, `BASH_ENV` and others) are refused.
- Downloading a schedule's install script no longer rotates its token: the file carries none, and that host reports through scans. A failed deploy no longer ends the old token. Reports never go to an address taken from a request's Host header: set a report URL, or runs arrive with the next scan.
- Bad or slow verify patterns can no longer lose a report or hold a web thread, and repeated report nonces are ignored.
- **Schedules no longer run on the StorageForge server.** The **Run local** button and `{"local": true}` are gone: they let an operator run commands where the vault secret lives. Use `storageforge-index schedule run` from a shell on the server.
- Creating, changing, pausing, running or deleting a schedule, and rotating its token, now asks for a fresh password. Running one also applies the deploy preflight.
- Schedules can no longer run destructive steps, which bypassed `deploy.destructive`. A schedule deployed with them keeps its old script until redeployed: it shows as changed on the Deploy tab.
- A schedule installed on a host can't be deleted until it is uninstalled. Ones already deleted get an **Uninstall** button on the Deploy tab.
- Git routes no longer run on the server when given `host=localhost`. Loopback names need a key bound to them, like any host.
- Accounts that can't edit schedules no longer see their commands or env values. Run output needs `logs.view`. Alert addresses in `/api/deploy` need `settings.manage`.
- `viewer` can no longer download a schedule's install script (which also minted a report token), its cron line or a host configuration bundle. These now need `plans.scripts`.

- **Report sections** for deployed jobs with their last runs, storage tasks, open alerts and drift, capacity trend, shares, unreadable folders, git repositories and containers.
- **Backups in the web UI**, with an optional copy of each backup to another host over SSH. A failed copy raises an alert.
- **Roles and accounts in the web UI:** change your own password, and admins can add, disable and remove accounts. `viewer` browses and searches, `operator` also plans, scans and deploys, `admin` also handles keys, accounts and settings. Existing accounts stay admins.
- **Retire a host** from its menu or with `hosts remove`, and remove keys and bindings from the Keys tab.
- **Per-host scan schedules:** a host can have its own interval and quiet hours, from its menu in the topology.
- **Designs stage pool tasks:** a new ZFS pool, ZFS datasets, a new LVM volume group and its volumes now become change-plan tasks instead of "by hand" notes.
- **3-2-1 matrix from what is deployed:** mirror and rsnapshot jobs and scheduled storage tasks fill the sync, snapshot and backup cells with their last good run. Typed values stay where nothing covers a dataset, and hosts can be marked offsite.
- **Move progress:** a move script run by hand now shows "copied" and "cut over" on its steps after the next scan.
- **Moves:** Duplicate and Export JSON. **Git:** select repositories and archive them together, and hide or show paths per host.
- **Storage tasks on the CLI:** `tasks list`, `check`, `script` and `import`.
- Storage task checks warn when a running container uses a block's source or destination.
- Shared test cases keep the planner's and the report's capacity numbers the same.
- **Shares manager in the topology:** a Shares button lists every share on the hosts in view, with access, client mounts, state and check problems, and opens designed shares to edit or remove. Editing and removing now find a share by its identity instead of its list position, which could change after a rescan and hit the wrong share. Wizard edits keep SMB settings and per-client mount options, a deployed share can be removed from the design, and saving a second copy of a share is refused.
- **Deploy run tracking and scan confirmation:** Scans verify completion records of deploy scripts (`/var/lib/storageforge/run/runs.jsonl`) and storage tasks (`/var/lib/storageforge/tasks/`) by matching run nonces, confirming actual host outcomes. If a run or task failed, StorageForge automatically runs a signed read-only log fetch over deploy access once per problem to capture runner and journal logs.
- **Deploy cancel and retry:** Running deploys can be stopped in the UI (with a Force stop option to terminate running SSH processes), and failed or interrupted deploys offer a Retry failed hosts button.
- **Stale dry run protection:** Applying a plan passes the dry run's group ID to ensure the plan was not modified after review.
- **Host configuration history and reinstall scripts:** each scan saves a host's fstab, crypttab, mdadm, NFS and Samba files, mounts, accounts and cross-mount symlinks when they change, with passwords removed. The new Rebuild tab and `storageforge-index config` show versions and what changed, and export a script that mounts every drive and subvolume on a fresh install, plus a `.tar.gz` to keep elsewhere. `STORAGEFORGE_CONFIG_EXPORT_DIR` writes that bundle every night.
- **Parallel scans:** up to `STORAGEFORGE_SCAN_WORKERS` hosts (default 4) scan at once, so a large or hung host no longer holds up the rest.
- **KVM lab:** `examples/lab` builds seven disposable VMs, picked at random from 14 configs across distros and filesystems, with a local control panel to create, reset and destroy them, StorageForge running on one VM, a demo that fills it with scans, shares, jobs and an alert, and test tiers including btrfs in depth, with a report per distro ([KVM lab](docs/kvm-lab.md)).
- **ZFS change tasks:** create a pool, create a dataset with properties, snapshot, scrub.
- **LVM change tasks:** create a volume group, add a device to one, create, grow and snapshot a logical volume.
- **Send over the network:** `btrfs-send` and `zfs-send` change tasks, and `btrfs_send` and `zfs_send` storage task blocks that send only the changes since the last shared snapshot, with "btrfs replication" and "ZFS replication" templates.
- **Alerts** for failed scans, missing mounts, nearly full filesystems, unhealthy pools and device errors, failed or old backups, and an expiring HTTPS certificate.
- CI for Forgejo Actions, ruff settings, `.env.example`, and guides for disaster recovery, troubleshooting and target hosts.

### Fixed
- **Container vulnerabilities:** the runtime image moved from Debian 12 to Debian 13 and installs Debian's security updates at build time. It no longer carries apt, perl, bash, tar, gzip, util-linux, PAM, Kerberos, ncurses or the sqlite3 shell, none of which it uses; `docker compose exec storageforge sh` still works. The ssh client is built from OpenSSH 10.6p1 because Debian 13's 10.0 has unpatched holes, so DSA host keys no longer work, as with any OpenSSH from 10.0. The proxy moved from nginx 1.27 to 1.30 pinned by digest, with its Alpine packages updated and curl removed. Grype on the runtime image: 5 critical and 84 high before, 0 critical and 13 high after.
- **Smoother Deploy tab:** Deploy panel polling updates output in-place preserving card expansion and scroll position; active deploys resume polling across tab reloads; the reporting settings form is kept across reloads; and deploy access removal uses a secure inline form instead of a plain-text prompt.
- An apply from the web UI rescans the hosts it ran on, so the other tabs show the result instead of waiting up to 6 hours for the next scan.
- A change plan that finished applying is no longer staged and moves to "Already ran" in the picker: deploy tracking ID matching is type-coerced, local drafts preserve clean state across reloads rather than forcing dirty state, and plans whose changes already exist on hosts offer one-click unstaging and mark as ran. Editing a plan makes it a plan to run again; one that skipped drive tasks stays unfinished and says so.
- An apply that left `missing` steps shows as `incomplete` instead of a green `ok`, for every kind of deploy, and a later scan keeps it that way.
- Share, change and move scripts run by hand end with "N step(s) not finished" instead of `done` when an apply left `missing` steps.
- A shares apply that left steps on the server is no longer marked as deployed.
- Move plans deployed as jobs are grouped under "Deployed as jobs" in the picker, until they are edited.
- Open tabs reload once the rescan after an apply ends.
- A refused deploy no longer fails with an internal error when it writes to the audit log.
- The git survey finds repositories when the host runs it with `dash`, instead of reporting none.
- `jobs.py` used f-string syntax that only Python 3.12 and later accept, though `pyproject.toml` promises 3.10.
- Two vault key derivations at once could hang, leaving deploys stuck and later scans failing with "Not enough memory to derive key" until a restart. They now run one at a time.
- A restart now marks unfinished deploy runs as failed, as it already did for scan jobs, instead of leaving them shown as running.
- `scan --host 127.0.0.1 --port 2222` scanned this machine instead of the SSH server on that port.
- Piping CLI output into a command that stops reading, such as `head`, no longer shows a traceback.
- Operations described a web backup button that does not exist.
